Status system — the honest-status contract
The 7 live statuses from hub-content.ts, each mapped onto an existing status token (no new colors). This is the single most-used visual signal in the product — it must be unmistakable and consistent everywhere.
Activated Needs setup Available Not probeable Reference Not checked Not found
Honest statusMeansMapped token
ActivatedLive probe returned 200 — provenstatus-signed (green)
Needs setup401/403 — comm arrangement not set upstatus-awaiting (amber)
AvailableEvent / subscribe-only — not pulledstatus-sent (blue)
Not probeableNo OData endpoint to probestatus-expired (grey)
ReferenceDesign-time contentstatus-draft (neutral)
Not found404 — not in this tenantstatus-revoked (red)
Rule carried into the design: a capability is shown Activated only where a live probe proved it; empty results render as “No records”, distinct from Needs-setup and from error. The colors never lie.

Frame

App shell & navigation
One internal console, three role-gated workspaces. Persistent chrome: a 56px top bar (product · breadcrumb · tenant switcher · environment · role · user) and a 220px left rail (workspace switcher + the active workspace’s sections). Everything else is content.
