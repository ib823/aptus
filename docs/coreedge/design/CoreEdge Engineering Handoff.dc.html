4 · Interaction notes

The rules that make the screens behave the way the flows imply. Where a rule exists to prevent a specific failure, the failure is named.
Focus order
Skip-to-content, then the rail as one stop (arrows move within, Enter opens), then the command bar, then content in reading order, then actions with destructive last. A five-row table is one tab stop with ↑ ↓ inside, so Tab crosses a screen in about seven presses rather than forty.
Disabled ≠ skipped
Disabled controls stay focusable and announce their reason: "Approve, unavailable: there’s no Prod SAP system yet." Removing them from the order hides the one sentence that explains the screen.
Keyboard shortcuts
⌘K command bar · Esc close and restore focus · Enter open or run · ↑ ↓ rows · Home/End jump. No single-letter shortcuts: the command bar covers those cases without colliding with typing.
Loading
Never blank a known state. A row being re-checked keeps its previous status and its age until its own check returns; skeletons appear only where nothing has ever loaded. There is no "checking" status — that would be a nineteenth vocabulary entry for a transient.
Empty
Empty is a sentence, not a blank panel. "No call with that ID in the last 30 days" states the retention window; "No ABeam app currently reads data from X5M" is the most reassuring screen in the product. A 0-row SAP response is gate-info, never an error.
Error
Every failure names the broken hop, the owner, and one action. Refusals are announced and move focus to the explanation, not to a toast; the Why? button is the next stop after it. A 401 and a 403 are never merged — they have different owners and different blast radii.
Toast copy
Toasts confirm, never explain: "Key revoked · Ikmal told, with the reason", "Deactivated · 4 builders told why", "Approved · Ikmal told", "Sent to SAP admin · 09:12". Anything a user may need to re-read belongs on the screen or the timeline, because a toast is gone in four seconds.
Optimistic updates
Only three: the rail badge counts, the step position in a flow, and text a user typed. Never a lane status, a key, an approval or a revoke — a lane that flashes green before SAP answers is the exact lie the whole design exists to prevent.
Age of proof
Every status renders with the age of the check behind it. Past 24 h a lane fades to Unknown rather than keeping a stale green; catalogue badges use 7 days. "Unknown" is a claim about us, not about the lane.
Concurrency
Two reviewers see the same queue and neither is assigned. The first decision closes it; a second attempt is refused and the dialog becomes the record — who decided, when, why. The same pattern covers revoke (platform admin and reviewer can both revoke) and deactivate.
Time
Store one UTC instant; render in the reader’s zone with the zone named. A bare date resolves to end-of-day in the requester’s zone and the resolution is shown before submit — 10 Dec 2026 → 2026-12-10T15:59:59Z, shown as "10 Dec 2026, 23:59 MYT". Relative time is a helper, never the fact.

6 · Behaviours the designs assume and the backend does not have

This is the estimating section. Each row is a capability the screens depend on; none of it is UI work. Sizes are relative, not days.

One-time claim linkMA tokenised URL that creates the key when opened, shows it once, and issues nothing at all if expired. !
Scheduled checks with a stored age are the load-bearing one. Eleven of the eighteen statuses, the entire Operations board, the 24 h fade to Unknown and every "proven N minutes ago" line depend on it. If only one item on this list ships, it should be that one — the rest degrade gracefully, and this one does not.

7 · Open questions for the product owner

Each one changes a screen. None is blocking a build start; all are cheaper to answer now than after.
#QuestionWhat we assumedWhat changes if the answer differs
Q1Do key prefixes encode the environment?We show ce_••••••7Kd uniformly, with ce_test_ noted as an open question rather than a design fact.If prefixes are environment-scoped, MaskedKey shows the environment and every key row gets a second identifying signal — which also makes "wrong key for this lane" diagnosable.
Q2Is 60 calls/min per key the right ceiling?60/min per key, refused before SAP. The number appears in copy on S14.A different ceiling is a copy change; a per-app or per-feed ceiling instead of per-key changes the S14 explanation and the key model’s blast radius.
Q3Who may revoke a key?Platform admin and reviewer. Operators flag and notify only (O08 → A05).If operators may revoke, O08 gains a destructive action and the red-for-irreversible rule reaches a third role. If only admins may, E2 loses its reviewer path.
Q4Can access be renewed without a fresh review?No. A reviewer requests a renewal and a colleague approves it (R07) — requester ≠ approver holds even for renewals.Auto-renewal on unchanged terms would remove R07’s second decision and the 30-day warning flow entirely.
Q5Is Sandbox always the SAP API Hub?Yes, and therefore never reviewed. That is why Sandbox never appears as a narrower approval option.A client-hosted sandbox with real data would make Sandbox reviewable and reintroduce the option we deliberately removed.
Q6What is the retention for calls and traces?30 days for correlation lookup (O09); timeline and audit kept for the life of the app, including after retirement.A shorter window changes O09’s empty-state copy, which states the window explicitly.
Q7Does the CIO passport need per-field detail?Counts plus a one-click field list per row (X06). No writes, every line with an approver and an end date.If a regulator needs the full field list inline, X06 becomes a much longer document and probably a scheduled export rather than a screen.
Q8Should the passport be self-serve for the client?Read-only, no actions, no Revoke button — governance rather than a kill switch.A client-triggered stop would need its own approval path, an SLA, and a state for "stopped by the client" in the vocabulary.
Q9Is there a second environment beyond the four?Exactly Sandbox, Dev, Test, Prod. O05’s migrated-data conflict is resolved by dropping a claim, not by adding an environment.A fifth environment changes the 4-up lane grid, the phone tab layout and the one-system-per-environment rule.
Q10Who owns the client SAP admin relationship?CoreEdge drafts the note from observed facts; an operator sends it. No SLA is claimed anywhere.If there is an SLA, the handoff card should show the clock — and "Mei Ling is on it" becomes a commitment with a deadline.
